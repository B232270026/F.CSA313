## 4. Ёс зүйн анхааруулга

Энэхүү лабораторийн load testing туршилтыг зөвхөн өөрийн локал орчинд ажиллуулсан API сервер дээр гүйцэтгэнэ.

Туршилтын target нь: `http://localhost:3000`

Иймээс k6-ээр үүсгэх бүх хүсэлт нь өөрийн компьютерт ажиллаж буй сервер рүү чиглэнэ.

Бусдын сервер, веб сайт эсвэл зөвшөөрөлгүй систем рүү их хэмжээний хүсэлт илгээж load testing хийх нь тухайн системийн хэвийн ажиллагаанд сөргөөр нөлөөлж болзошгүй бөгөөд DoS (Denial of Service) халдлагатай адил шинжтэй байж болно. Тиймээс энэ лабораторийн хүрээнд зөвшөөрөлгүй систем дээр load test хийхгүй.

Энэхүү туршилтын зорилго нь халдлага хийх бус, өөрийн API системийн performance, reliability болон availability шинжүүдийг аюулгүй локал орчинд хэмжиж, SLO болон k6 threshold ашиглан шалгах юм.

## 5. Тестлэх локал API-гаа босгох  

Энэхүү лабораторийн туршилтыг хийхийн тулд Node.js болон Express ашиглан локал API сервер үүсгэсэн. API сервер нь `localhost:3000` дээр ажиллах бөгөөд дараагийн k6 тестүүдэд performance, reliability болон availability шинжүүдийг шалгах зорилгоор гурван endpoint ашигласан.

API-ийн үндсэн бүтэц:

| Method | Endpoint    | Зориулалт                     |
| ------ | ----------- | ----------------------------- |
| POST   | `/cart/add` | Сагсанд бараа нэмэх           |
| GET    | `/report`   | Тайлангийн мэдээлэл авах      |
| POST   | `/pay`      | Төлбөрийн хүсэлт боловсруулах |

## 4.1 `/cart/add`

`/cart/add` endpoint нь хэрэглэгч сагсанд бараа нэмэх үйлдлийг төлөөлнө. Энэ endpoint-д зориудаар нэмэлт delay болон failure оруулаагүй бөгөөд амжилттай хүсэлтэд `HTTP 200` хариу буцаана.

```json
{
  "ok": true,
  "items": 1
}
```

Энэ endpoint-ийг **Performance scenario**-д ашигласан. Учир нь нэмэлт delay байхгүй тул хэвийн ачааллын үед response time-ийг хэмжихэд тохиромжтой.

## 4.2 `/report`

`/report` endpoint нь тайлан боловсруулах үйлдлийг төлөөлнө. Performance тестийн үед response time тодорхой хэмжээнд удаан байх нөхцөлийг бий болгохын тулд 200–400 миллисекундын санамсаргүй delay оруулсан.

```js
await sleep(200 + Math.random() * 200);
```

Амжилттай хүсэлтийн үед:

```json
{
  "rows": 20000
}
```

гэсэн response буцаана.

Энэ endpoint-ийг нэмэлт **Performance scenario**-д ашиглаж, response latency-ийн `p95` утгыг хэмжинэ.

## 4.3 `/pay`

`/pay` endpoint нь хэрэглэгчийн төлбөр хийх үйлдлийг төлөөлнө. Reliability scenario-д системийн failure rate-ийг хэмжихийн тулд хүсэлтийн ойролцоогоор 5%-д `HTTP 500` алдаа буцаахаар тохируулсан.

```js
if (Math.random() < 0.05) {
  return res.status(500).json({
    error: 'gateway timeout'
  });
}
```

Алдаа гараагүй тохиолдолд төлбөр амжилттай болсон тухай response буцаана.

Энэхүү зориудаар үүсгэсэн failure нь `/pay` endpoint-ийн **error rate**-ийг k6 ашиглан хэмжих боломжийг бүрдүүлсэн. Reliability scenario-ийн SLO-д уг error rate-ийг ашиглана.

### 6.1 Performance сценарио - /cart/add

| Хэсэг                | Сценарио                                                                       |
| ---------------------- | ------------------------------------------------------------------------------ |
| **Тойм**               | Хэрэглэгч сагсанд бараа нэмэх үед API-ийн гүйцэтгэлийг шалгана. Ачаалал хэвийн байх үед хурдан ажиллах ёстой.                |
| **Системийн төлөв**    | API сервер хэвийн ажиллаж, хэрэглэгчийн хүсэлтийг хүлээн авч байна.            |
| **Орчны төлөв**        | Node.js + Express API, localhost орчинд ажиллаж, 20 VU хэвийн ачаалал үүсгэнэ. |
| **Гадаад өдөөлт**      | 20 зэрэгцээ хэрэглэгч `/cart/add` endpoint руу бараа нэмэх хүсэлт илгээнэ. Test window нь 1 минут.     |
| **Шаардлагатай хариу** | Сервер хүсэлтийг амжилттай боловсруулж HTTP 200 хариу буцаана.                 |
| **Хэмжүүр**            | `/cart/add` endpoint-ийн response time-ийн p95 нь 50 ms-ээс бага байна.       |

### 6.2 Reliability сценарио - /pay

| Хэсэг                  | Сценарио                                                                  |
| ---------------------- | ------------------------------------------------------------------------- |
| **Тойм**               | Хэрэглэгч төлбөр хийх үед системийн найдвартай ажиллагааг шалгана. Төлбөр амжилтгүй болох магадлал нь тогтоосон хэмжээнээс хэтрэхгүй байх ёстой.      |
| **Системийн төлөв**    | API сервер хэвийн ажиллаж, хэрэглэгч төлбөр хийх боломжтой байна.         |

| Хэсэг                  | Сценарио                                                                                     |
