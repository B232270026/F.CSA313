## 1. Лабораторийн ажлын зорилго

Энэхүү лабораторийн ажлын зорилго нь Playwright framework ашиглан веб системийн функциональ автомат тест боловсруулах, тестийн үр дүнг шалгах, Trace Viewer ашиглан тестийн ажиллагааг шинжлэхэд оршино.

Лабораторийн ажлын хүрээнд дараах зүйлсийг гүйцэтгэсэн.
- Playwright төслийг үүсгэж, шаардлагатай browser-уудыг суулгах.
- Locator ашиглан веб элементүүдтэй харилцах.
- Амжилттай болон амжилтгүй нэвтрэх тест боловсруулах.
- Нэвтэрсний дараа барааг сагсанд нэмэх үйлдлийг шалгах.
- Assertion ашиглан хүлээгдэж буй үр дүнг баталгаажуулах.
- Codegen ашиглан тестийн код автоматаар үүсгэх.
- Trace Viewer ашиглан тестийн үйлдэл болон алдааг шинжлэх.
- Тестийг санаатайгаар унагаж, алдааг Trace Viewer ашиглан мөшгөх.

**Зорилго:** Зөв хэрэглэгчийн нэр, нууц үг ашиглан системд амжилттай нэвтэрч болох эсэхийг шалгах.

2. Хэрэглэгчийн нэрд `standard_user` оруулах.

5. Бүтээгдэхүүний хуудас нээгдсэн эсэхийг шалгах.
6. Logout хийж системээс гарсан эсэхийг шалгах.

**Баталгаажуулалт:**

- URL нь `inventory.html` агуулсан байх.

**Зорилго:** Буруу нууц үг ашигласан үед систем нэвтрэхийг зөвшөөрөхгүй, алдааны мэдээлэл харуулах эсэхийг шалгах.

**Тестийн алхам:**

1. SauceDemo системийг нээх.
2. Хэрэглэгчийн нэрд `standard_user` оруулах.
3. Буруу нууц үг оруулах.

**Баталгаажуулалт:**

## 5. Locator болон Assertion ашиглалт

Тест боловсруулахдаа веб элементүүдийг тодорхойлохын тулд Playwright-ийн locator-уудыг ашигласан.

| Locator / Assertion | Зориулалт |
|---|---|
| `getByPlaceholder()` | Placeholder утгаар input талбарыг олох |
| `getByRole()` | Элементийн role болон нэрээр олох |
| `getByText()` | Текстийн утгаар элемент олох |
| `locator()` | CSS selector болон attribute ашиглан элемент олох |
| `toBeVisible()` | Элемент харагдаж байгаа эсэхийг шалгах |
| `toHaveURL()` | Хуудасны URL шалгах |
| `toHaveText()` | Элементийн текстийг шалгах |
| `toContainText()` | Текстийн агуулгыг шалгах |

Playwright-ийн semantic locator болох `getByRole()`, `getByText()`, `getByPlaceholder()` нь веб элементийг хэрэглэгчид харагдах шинж чанараар тодорхойлоход тохиромжтой. Харин CSS selector ашиглах үед тухайн системийн `data-test` зэрэг attribute-д тулгуурлан элемент сонгож болно.

XPath locator ашиглахаас зайлсхийсэн. Учир нь XPath нь DOM бүтцийн өөрчлөлтөөс хамааралтай болж, тестийг арчлахад хүндрэл үүсгэж болзошгүй.

## 6. Codegen туршилт

Playwright Codegen ашиглан SauceDemo систем дээрх нэвтрэх болон барааг сагсанд нэмэх үйлдлүүдийг хийж, автомат үүсгэсэн TypeScript кодыг `results/codegen-generated.spec.ts` файлд хадгалсан.

Ажиллуулсан команд:

```bash
npx playwright codegen https://www.saucedemo.com/
```

Codegen-ээр үүссэн кодыг өөрийн бичсэн `tests/mytest.spec.ts` файлтай харьцуулсан.

Codegen нь browser дээр хийсэн үйлдлүүдэд тохирох locator болон action-уудыг автоматаар үүсгэдэг. Харин өөрийн бичсэн тестэд `login()` болон `logout()` helper функц, assertion, тестийн нэршил, шалгах нөхцөлүүдийг нэмж зохион байгуулсан. Codegen-ээр үүссэн кодод Sauce Labs Fleece Jacket барааг сагсанд нэмэх үйлдэл бүртгэгдсэн бол өөрийн боловсруулсан тестэд Sauce Labs Backpack барааг сонгон шалгах нөхцөлийг тусгасан.

**Нотолгоо:** `results/codegen-generated.spec.ts`

## 7. Trace Viewer туршилт

Тестийн үйлдлүүдийг бүртгэж, дараа нь шинжлэх зорилгоор Playwright Trace Viewer ашигласан.

Тестийг trace-тэй ажиллуулах команд:

```bash
npx playwright test tests/mytest.spec.ts --trace on
```

Trace Viewer нээх команд:

```bash
npx playwright show-trace <trace-file-path>
```

Trace Viewer ашиглан дараах мэдээллийг шалгасан.

- **Actions:** Тестийн үйлдлүүдийн дараалал.
- **Source:** Ажилласан тестийн код.
- **Snapshots:** Үйлдлийн өмнөх болон дараах хуудасны төлөв.
- **Errors:** Тестийн алдааны мэдээлэл.
- **Network:** Сүлжээний хүсэлтүүд.

Тест тус бүрийн trace файлыг `results/` хавтсанд тусад нь хадгалсан.

| Файл | Тестийн төрөл |
|---|---|
| `trace-success.zip` | Амжилттай нэвтрэх |
| `trace-failed-login.zip` | Буруу нууц үгээр нэвтрэх |
| `trace-add-to-cart.zip` | Барааг сагсанд нэмэх |
| `trace-intentional-failure.zip` | Санаатайгаар унагасан тест |

## 8. Тестийг санаатайгаар унагах туршилт

Playwright-ийн assertion алдааг хэрхэн илрүүлж, мэдээлдэгийг судлахын тулд амжилттай нэвтрэх тестийн assertion-ийг түр хугацаанд буруу болгосон.

Анхны зөв assertion:

```ts
await expect(page.getByText('Products')).toBeVisible();
```

Санаатайгаар буруу болгосон assertion:

```ts
await expect(page.getByText('Wrong Products')).toBeVisible();
```

Тестийг зөвхөн Chromium browser дээр ажиллуулсан:

```bash
npx playwright test tests/mytest.spec.ts \
  --grep "Амжилттай нэвтрэх" \
  --project=chromium \
  --trace on \
  --output=test-results-intentional-failure
```

Үр дүнг `results/intentional-failure.txt` файлд хадгалсан.

Тестийн үр дүнд `Wrong Products` гэсэн элемент хуудаснаас олдоогүй тул `toBeVisible()` assertion амжилтгүй болж, тест `1 failed` үр дүнтэй дууссан.

Үүссэн trace файлыг `results/trace-intentional-failure.zip` нэрээр тусад нь хадгалж, Trace Viewer дээр нээсэн. Actions болон Errors хэсгүүдээр алдаа гарсан үйлдэл, assertion-ийн алдааны шалтгааныг шалгасан.

Туршилтын дараа буруу assertion-ийг анхны `Products` утгаар сэргээсэн.

## 10. Playwright ба Selenium-ийн харьцуулалт

Playwright болон Selenium нь веб системийн автомат тест хийхэд ашиглагддаг framework-ууд юм. Playwright нь Chromium, Firefox, WebKit browser-уудыг шууд дэмждэг бол Selenium нь WebDriver протокол ашиглан олон төрлийн browser-той ажилладаг. Playwright нь auto-waiting механизмтай тул элемент үйлдэл хийхэд бэлэн болохыг автоматаар хүлээдэг. Selenium-д ийм нөхцөлд explicit wait ашиглах шаардлага илүү түгээмэл байдаг. Playwright нь Trace Viewer, Codegen зэрэг тест боловсруулах болон алдаа шинжлэхэд туслах хэрэгслүүдтэй. Харин Selenium нь олон хэлний binding болон өргөн хүрээний экосистемтэй. Playwright нь browser automation болон end-to-end тестийг хурдан боловсруулахад тохиромжтой. Selenium нь олон төрлийн хэл, browser, тестийн орчинтой уялдуулах шаардлагатай үед давуу талтай.

## 11. Дүгнэлт

Энэхүү лабораторийн ажлаар Playwright framework ашиглан SauceDemo веб системд функциональ автомат тест боловсруулсан. Амжилттай нэвтрэх, буруу нууц үгээр нэвтрэх болон барааг сагсанд нэмэх гэсэн гурван үндсэн үйлдлийг шалгасан. Тестийн явцад `getByRole()`, `getByText()`, `getByPlaceholder()` зэрэг locator болон assertion-уудыг ашиглаж сурсан. Codegen ашиглан үйлдлээс тестийн код автоматаар үүсгэж, өөрийн бичсэн кодтой харьцуулсан. Trace Viewer ашиглан тестийн үйлдлийн дараалал, хуудасны төлөв болон алдааны мэдээллийг шинжилсэн. Мөн assertion-ийг зориудаар буруу болгож тестийг унагах замаар Playwright алдааг хэрхэн илрүүлж байгааг туршсан. Алдаатай тестийн trace-ийг тусад нь хадгалж, алдааны шалтгааныг Trace Viewer дээр шалгасан. Эцэст нь тестийн кодыг сэргээж, бүх browser дээр дахин ажиллуулан үр дүнг баталгаажуулсан.

## 12. AI ашиглалтын тухай

Лабораторийн ажлын явцад Playwright-ийн талаар сайн мэдэхгүй байсан зүйлсээ тодруулах, командуудын зориулалт болон ажиллах зарчмыг ойлгохын тулд AI-аас зөвлөгөө авсан. Өгсөн тайлбар, зөвлөмжийг лабораторийн заавар болон төслийн бодит үр дүнтэй тулган нягталж ашигласан. AI-г кодыг бүхэлд нь бичүүлэхээс илүүтэйгээр ойлголтоо сайжруулах, тулгарсан асуудлын шалтгааныг тодруулахад туслах хэрэгсэл болгон ашигласан. Playwright-ийн талаар ойлгомжгүй, сайн мэдэхгүй байсан зүйлсээ AI-аас асууж, командуудын зориулалт болон ажиллах зарчмын талаар тайлбар авсан. Авсан зөвлөгөөг шууд хуулбарлан ашиглахын оронд лабораторийн заавар, төслийн код болон бодит үр дүнтэй тулган шалгасан. Тестүүдийг өөрөө бичиж, терминалаар ажиллуулан үр дүнг баталгаажуулсан. Codegen, Trace Viewer болон санаатайгаар тест унагах туршилтуудыг өөрөө гүйцэтгэж, үүссэн нотолгооны файлуудыг шалгасан.
