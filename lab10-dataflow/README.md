# ХЭСЭГ A — GCD функцийн DU шинжилгээ

## A1. Функцийн шинжилгээ

`DataFlowTargets.java` файлын `gcd(int x, int y)` функц нь Евклидийн алгоритмаар хоёр бүхэл тооны хамгийн их ерөнхий хуваагчийг олно.

```java
public static int gcd(int x, int y) {
    int tmp;
    while (y != 0) {
        tmp = x % y;
        x = y;
        y = tmp;
    }
    return x;
}
```

Хувьсагчдын тодорхойлолт болон хэрэглээ:

| Хувьсагч | Definition | Use |
|---|---|---|
| `x` | 13, 17-р мөр | 16, 20-р мөр |
| `y` | 13, 18-р мөр | 15, 16, 17-р мөр |
| `tmp` | 16-р мөр | 18-р мөр |

`c-use` нь тооцоолол, илэрхийлэлд хувьсагч ашиглагдахыг илэрхийлнэ. `p-use` нь нөхцөл шалгах үед хувьсагч ашиглагдахыг илэрхийлнэ.

| 1 | x | 13 | 16 | c-use | 13 → 15(T) → 16 | G3 |
| 2 | x | 13 | 20 | c-use | 13 → 15(F) → 20 | G1 |

# ХЭСЭГ B — BONUS функцийн бүрэн шинжилгээ

## B1. Control Flow Graph (CFG)

`bonus(int[] attendance, int threshold)` функц нь ирцийн массив болон босго утгыг ашиглан оноо тооцоолно.

CFG диаграммыг `cfg-bonus.png` нэрээр хадгалсан.

Диаграммд дараах үндсэн урсгалуудыг тусгасан:

1. Эхлэх болон оролтын параметр шалгах.
2. `attendance == null` эсэхийг шалгах.
3. `threshold < 0` эсэхийг шалгах.
4. `present`, `streak`, `best` хувьсагчдыг эхлүүлэх.
5. For-each давталтын дараагийн элемент байгаа эсэхийг шалгах.
6. Дараагийн элементийг `a` хувьсагчид оноох.
7. `a > 0` нөхцөлийг шалгах.
8. Ирцтэй үед `present`, `streak`-ийг шинэчлэх.
9. `streak > best` нөхцөлөөр хамгийн урт дарааллыг шинэчлэх.
10. Ирц тасарсан үед `streak = 0` болгох.
11. Давталт дууссаны дараа `score` тооцоолох.
12. Босго болон дараалсан ирцийн нөхцөлөөр оноо нэмэх.
13. Эцсийн оноог буцаах.

For-each давталтын 38-р мөрийг CFG-д хоёр тусдаа үйлдлээр дүрсэлсэн:

- `attendance` массивт дараагийн элемент байгаа эсэх — `attendance` хувьсагчийн p-use.
- Дараагийн элементийг `a` хувьсагчид оноох — `a` хувьсагчийн def.

Зангилаа бүрд эх кодын мөрийн дугаарыг тэмдэглэж, салаалсан ирмэгүүдэд тестийн method нэрийг оруулсан.

### B3.8. Kill буюу дахин тодорхойлолт

46-р мөрийн `streak = 0` нь өмнөх `streak` хувьсагчийн тодорхойлолтыг хүчингүй болгоно. Иймээс 41-р мөрийн Def-ээс дараагийн Use рүү хүрэх замд 46-р мөрөөр дамжвал тухайн Def-clear зам тасарна.

Мөн дараах дахин тодорхойлолтуудыг тооцсон:

- 41-р мөрийн `streak = streak + 1` нь өмнөх `streak`-ийн Def-ийг шинэчилнэ.
- 43-р мөрийн `best = streak` нь 37-р мөрийн `best = 0` тодорхойлолтыг шинэчилнэ.
- 51-р мөрийн `score = 5` нь 49-р мөрийн `score = 0` тодорхойлолтыг хүчингүй болгоно.
- 54-р мөрийн `score = score + 3` нь `score`-ийн шинэ Def үүсгэнэ.

Иймээс kill-ээр тасарсан Def–Use хослолыг боломжтой DU хос гэж тооцоогүй.

### B3.9. Биелэшгүй DU хосын үндэслэл

`best` хувьсагчийн 37-р мөрийн анхны тодорхойлолтоос 42-р мөрийн False салаанд хүрэх боломжгүй. Учир нь `streak` эхэндээ 0 бөгөөд эхний эерэг ирц дээр 1 болж, `best = 0`-ээс их болох тул 42-р мөр True болж 43-р мөрөөр `best` дахин тодорхойлогдоно.

37-р мөрийн `best` тодорхойлолтоос 53-р мөрийн True салаанд хүрэх боломжгүй. Учир нь `best >= 5` болохын тулд 43-р мөрийн шинэ тодорхойлолт ажилласан байх шаардлагатай бөгөөд энэ нь 37-р мөрийн Def-ийг kill хийнэ.

`attendance == null` үед 32-р мөрийн `||` богино холболтын улмаас `threshold < 0` шалгалт ажиллахгүй. Иймээс null attendance болон negative threshold-ийн True нөхцөлийг нэг гүйцэтгэлд хамтад нь шалгах боломжгүй.

# ХЭСЭГ C — Fault Seeding: Урсгалын алдаа тарих

## C1. Туршилтын зорилго

Fault Seeding нь эх кодод зориудаар алдаа оруулж, боловсруулсан тестүүд тухайн алдааг илрүүлж чадаж байгаа эсэхийг шалгах арга юм.

Энэ лабораторид гурван төрлийн мутаци хийсэн:

| Мутаци | Төрөл | Өөрчлөлт |
|---|---|---|
| M1 | Missing update | `streak = streak + 1` мөрийг устгах |
| M2 | Wrong variable | `best = streak`-ийг `best = present` болгох |
| M3 | Dead definition | `int total = present + best;` нэмэх |

Мутаци бүрийг нэг нэгээр нь хийж, `mvn test` ажиллуулан үр дүнг хадгалсан. Туршилт бүрийн дараа `git restore` ашиглан `DataFlowTargets.java` файлыг анхны төлөвт сэргээсэн.

## C2. M1 — Missing update

M1 мутацийн үед:

```java
streak = streak + 1;
```

гэсэн мөрийг түр устгасан.

Ингэснээр `streak` хувьсагчийн утга нэмэгдэхгүй болж, дараалсан ирцийн тооцоолол алдагдсан.

`mvn-test-M1.txt` үр дүн:

```text
Tests run: 11, Failures: 2, Errors: 0, Skipped: 0
BUILD FAILURE
```

Унасан тестүүд:

**1.** `bonus_brokenThenStreak5_belowThreshold_returns3`

```text
expected: <3> but was: <0>
```

**2.** `bonus_fivePresent_meetsThreshold_returns8`

```text
expected: <8> but was: <5>
```

Эдгээр тестүүд дараалсан ирцийн тоог ашиглан нэмэлт оноо тооцоолдог. `streak` шинэчлэгдэхээ больсноор `best >= 5` нөхцөл хангагдахгүй болж, хүлээгдэж байсан нэмэлт оноо олгогдоогүй.

**Дүгнэлт:** M1 мутацийг одоогийн тестүүд амжилттай илрүүлсэн.

## C3. M2 — Wrong variable

M2 мутацийн үед:

Анхны код:

```java
if (streak > best) {
    best = streak;
}
```

Мутацитай код:

```java
if (streak > best) {
    best = present;
}
```

Энэ өөрчлөлтөөр хамгийн урт дараалсан ирцийн оронд нийт ирцийн тоог `best` хувьсагчид оноодог болсон.

### M2-ийн эхний туршилт

T1–T7 тестүүдээр `mvn test` ажиллуулсан.

`mvn-test-M2.txt` үр дүн:

```text

BUILD SUCCESS
```

Энэ мутаци эхний ALL-DU-PAIRS тестүүдээр илрээгүй.

Учир нь тухайн тестүүдэд `best` шинэчлэгдэх үед нийт ирцийн тоо болон дараалсан ирцийн тоо хоёулаа нэмэлт оноо авах нөхцөлийг хангаж байсан. Иймээс буруу хувьсагч ашигласан ч тестүүдийн хүлээгдэж буй үр дүн өөрчлөгдөөгүй.

## C4. M3 — Dead definition

M3 мутацийн үед давталтын дараа дараах мөрийг нэмсэн:

M3 нь Dead Definition буюу цаашид ашиглагдахгүй тодорхойлолтын жишээ юм. Ийм асуудлыг зөвхөн функциональ тестээр илрүүлэх боломжгүй. IDE-ийн static analysis, code inspection болон статик шинжилгээний хэрэгслүүд ашиглагдаагүй хувьсагчийг илрүүлэхэд тохиромжтой.

**Дүгнэлт:** M3 мутаци тестүүдээр илрээгүй. Энэ нь тестийн хамралт өндөр байсан ч ашиглагдаагүй кодын тодорхойлолт зэрэг асуудлыг статик шинжилгээгээр тусад нь шалгах шаардлагатайг харуулсан.
