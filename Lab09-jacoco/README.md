## 2. Лабораторийн зорилго

Энэхүү лабораторийн ажлын зорилго нь Java программын код хамралтыг JaCoCo хэрэгслээр хэмжих, тестийн хамрах хүрээг үе шаттай нэмэгдүүлэх, Control Flow Graph (CFG) ашиглан салаалсан логикийг шинжлэх, давталтын заагийн тест болон зааг утгын тест боловсруулахад оршино.

Лабораторийн хүрээнд `ScholarshipCalculator` классын дараах гурван методыг тестэлсэн:

- `letterGrade(double score)` - өгсөн оноонд тохирох үсгэн үнэлгээ буцаана.
- `gpa(double[] scores)` - үнэлгээнүүдийн голч дүнг тооцоолно.
- `scholarship(double gpa, int credits, boolean hasViolation)` - голч, кредит болон сахилгын зөрчлөөс хамааруулан тэтгэлгийн хэмжээг тодорхойлно.

## 4. B хэсэг — Branch coverage ба Control Flow Graph

## 5. C хэсэг — Давталтын заагийн тест

Энэ хэсэгт `gpa()` методын `for` давталтын 0, 1 болон 2-оос олон удаагийн гүйцэтгэлийг шалгасан.

Давталтын заагийн тестүүд:

| Тестийн метод | Оролт | Хүлээгдэж буй үр дүн |
|---|---|---|
| `shouldThrowExceptionForEmptyScores` | Хоосон массив `{}` | `IllegalArgumentException` |
| `shouldThrowExceptionForNullScores` | `null` | `IllegalArgumentException` |
| `shouldCalculateGpaForOneScore` | `[95]` | `4.0` |
| `shouldCalculateGpaForMultipleScores` | `[95, 85, 75, 65]` | `2.5` |

Хоосон болон `null` массивын тестүүд B хэсэгт аль хэдийн нэмэгдсэн тул давхар метод үүсгээгүй. C хэсэгт нэг элементтэй болон олон элементтэй массивын хоёр шинэ тест нэмсэн.

Эдгээр тест нь кодын хамралтын хувийг заавал нэмэгдүүлэхгүй боловч давталтын 0, 1, 2+ удаагийн гүйцэтгэлийн үед логик зөв ажиллаж байгаа эсэхийг шалгадаг. Ялангуяа хоосон массив, ганц элементтэй массив болон олон элементтэй массивын голч тооцоололд алдаа гарахаас сэргийлэх ач холбогдолтой.

## 6. D хэсэг — Зааг утгын тест ба алдааг илрүүлж засах

Энэ хэсэгт `letterGrade()` методын зааг утгуудыг шалгах 7 тест нэмсэн.

Шалгасан утгууд:

| Оноо | Хүлээгдэж буй үнэлгээ |
|---:|---|
| 60 | D |
| 59.99 | F |
| 69.99 | D |
| 0 | F |
| 100 | A |
| 89.99 | B |
| 90 | A |

### 6.1. Алдааг илрүүлсэн үр дүн

Эхний `mvn test` ажиллуулахад нийт 32 тестээс 1 тест унаж, 0 error гарсан.

Унасан тестийн нэр:

`shouldReturnGradeDFor60`

`results/mvn-test-D-fail.txt` файлаас авсан алдааны мөр:

```text
expected: <D> but was: <F>
```

Алдаа гарсан тестийн байршил:

`ScholarshipCalculatorTest.java:165`

Алдааны шалтгаан нь `letterGrade()` методод 60 оноог D үнэлгээнд хамруулах ёстой байхад `score > 60` гэсэн харьцуулах оператор ашигласан явдал байв. Иймээс оноо яг 60 байх үед нөхцөл худал болж, метод буруу үр дүн буюу F буцааж байсан.

### 6.2. Алдааг зассан нь

Дараах код:

```java
if (score > 60) return "D";
```

дараах байдлаар өөрчлөгдсөн:

```java
if (score >= 60) return "D";
```

Ингэснээр 60 оноо D үнэлгээнд зөв хамрагдах болсон.

### 6.4. Гол дүгнэлт

Өмнөх тестүүд нөхцөлийн хоёр салааг ажиллуулсан тул branch coverage өндөр байсан боловч 60 гэсэн зааг утгыг шалгаагүй учраас логик алдаа илрээгүй. score > 60 нөхцөл нь яг 60 оноог D үнэлгээнд оруулахгүй байсан. shouldReturnGradeDFor60 тестээр энэ алдаа илэрч, нөхцөлийг score >= 60 болгон зассан. Зөвхөн 60 гэсэн утгыг тусгайлан шалгасан зааг утгын тест алдааг илрүүлсэн. Код хамралт нь тестүүд кодын мөр болон салааллыг ажиллуулсан эсэхийг хэмждэг боловч тухайн кодын үр дүн спецификацитай нийцэж байгаа эсэхийг баталдаггүй. Иймээс 100% хамралттай байсан ч логик алдаа үлдэх боломжтой. Энэ туршилт нь branch coverage болон тестийн чанар хоёр өөр ойлголт болохыг харуулсан.

**Алдааг зассан Git commit-ийн мессеж:**

`Fix letterGrade: > 60 to >= 60, spec says 60 is D`

## 7. Нэмэлт даалгавар — JaCoCo Coverage Gate ба GitHub Actions CI

Нэмэлт даалгаврын хүрээнд JaCoCo Maven Plugin-ийн `check` goal ашиглан branch coverage-ийн доод босгыг 90% болгон тохируулсан.

`pom.xml` файлд дараах тохиргоог нэмсэн:

- Counter: `BRANCH`
- Value: `COVEREDRATIO`
- Minimum: `0.90`

Ингэснээр branch coverage 90%-иас доош тохиолдолд Maven build амжилтгүй болох нөхцөл бүрдсэн.

Мөн GitHub Actions ашиглан CI workflow үүсгэсэн. `.github/workflows/ci.yml` файлд Java 17 орчныг тохируулж, кодыг `main` branch руу push хийх болон pull request үүсгэх үед `mvn -B clean verify` командыг автоматаар ажиллуулахаар тохируулсан.

Локал орчинд `mvn clean verify` ажиллуулахад 32 тест бүгд амжилттай болж, JaCoCo coverage gate-ийн шалгалт:

`All coverage checks have been met.`

гэсэн үр дүнтэй дууссан.

Эцсийн build:

`BUILD SUCCESS`
